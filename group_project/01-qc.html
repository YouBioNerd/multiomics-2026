Study B (contraception) — QC before analysis

Quality control: checking the data for problems before we run any tests. If a sample has almost no reads, or a table doesn’t line up with the sample list, any test we run afterwards would be quietly wrong. Better to find that now.

There are three count-like tables in Study B: the microbiome (species), the RNA-seq (genes), and the cytokines. We check them one at a time.

# here() finds files relative to the project folder, no matter where the
# notebook is opened from. count_tables.R is the workshop helper that loads
# a dataset and lines up the tables for us.

2. Do the count tables line up with the sample table?

The count tables have samples as columns. Every test this week assumes the columns are in the same order as the rows of the sample table. If they matched by name but not by order, R would happily compare sample 5’s counts with sample 6’s metadata — and never warn us.

# identical() asks: are these two character vectors EXACTLY the same,
# in the same order? TRUE is what we want.
identical(colnames(d$species), d$metadata$sample_id)   # species table
[1] TRUE
identical(colnames(d$genes),   d$metadata$sample_id)   # gene table
[1] TRUE

Both come out TRUE because read_counts() puts the columns in metadata order as it loads them. Had we loaded the files by hand, this is the check we would have had to do ourselves.

3. Species table — depth and detection

Two basic questions per sample:

  • Library size (also called depth): total reads in the sample. A sample with far fewer reads than its neighbours saw less, so its counts are noisier.
  • Features detected: how many species were seen at least once. A sample that detected half as many species as usual may have been under-sequenced.
# Everything is computed column-wise: one column of the count matrix = one sample.
species_qc <- tibble(
  sample            = colnames(d$species),
  library_size      = colSums(d$species),
  features_detected = colSums(d$species > 0),
  # colMeans(d$species > 0) gives, per sample, the share of species DETECTED;
  # 1 minus that is the share of cells that are zero.
  fraction_zeros    = 1 - colMeans(d$species > 0)
)

4. Gene table — depth and detection

Same checks for the RNA-seq table. Depths here are in the millions, and detection is nearly total (most genes get at least a few reads in every sample), so the numbers look completely different — that’s expected, not a bug.

genes_qc <- tibble(
  sample            = colnames(d$genes),
  library_size      = colSums(d$genes),
  features_detected = colSums(d$genes > 0)
)

genes_qc |>

5. Sequencing batch

The gene table was sequenced in two batches (B1, B2). Batches are a classic source of technical differences that have nothing to do with biology, so we check whether batch and depth are tangled up with each other.

genes_qc |>
  left_join(d$metadata, by = c("sample" = "sample_id")) |>   # bring the batch label over
  ggplot(aes(rnaseq_batch, library_size, fill = rnaseq_batch)) +
  geom_boxplot(show.legend = FALSE) +
  geom_jitter(width = 0.15, alpha = 0.4) +
  labs(title = "Gene library size by sequencing batch",
       x = "Batch", y = "Library size (reads)")
# Are the arms spread across both batches, or is one arm all in one batch?
count(d$metadata, arm, rnaseq_batch) |>
  pivot_wider(names_from = rnaseq_batch, values_from = n)
# A tibble: 3 × 3
  arm           B1    B2
  <chr>      <int> <int>
1 injectable    20    19
2 pill          14    14
3 ring          13    13

If batch and arm were tangled, a real difference between arms would be impossible to tell apart from a batch effect. Here they’re mixed, which is what we want — but keep batch in mind for the analysis.

Verdict

  • Sample table: clean — 93 samples, one per participant, no missing values, arms reasonably balanced.
  • Alignment: both count tables line up with the metadata, in order.
  • Species table: ~88% zeros (normal), depths span roughly 5k to 77k reads. The low end is thin; check the flagged samples above before differential testing.
  • Gene table: millions of reads per sample, nearly all genes detected, depths within a few-fold of each other. Batches are balanced across arms.
  • Cytokines: a handful of missing values to handle when we get there.

No sample needs to be dropped on the evidence so far. The analysis notebooks should use raw counts (not CPM, not logged) for DESeq2, and should keep an eye on batch.

Choices made

  • Flagged low-depth samples at below half the median library size; an alternative is the bottom decile, or a fixed threshold, which would flag a different set.
  • Checked library size and features detected as the two core QC metrics; an alternative is adding Shannon diversity here, which notebook 03 covers anyway.
  • Plotted QC per sample rather than summarising to per-arm means, because QC problems are sample-level, not group-level.
  • Checked batch balance descriptively (a table and a boxplot); an alternative is testing it formally, which we save for the analysis itself.
